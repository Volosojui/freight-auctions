## Context

Greenfield-репозиторий без кода. Стек и требования зафиксированы в ТЗ (`docs/project_requirements.md`) и обязательны: React, TypeScript, Vite, TanStack Router, TanStack Query, RHF+Zod, MSW, Feature-Sliced Design, MobX для точечного UI-state. Источник правды по контракту — `docs/openapi.auctions.v0.json`. См. `proposal.md` — Why. Этот change отвечает за каркас; контрактный слой и фичи идут отдельными change'ами.

## Goals / Non-Goals

**Goals:**
- Единый предсказуемый каркас FSD, на который последующие change'и добавляют слайсы, не переструктурируя проект.
- Data-layer провайдеры и роутинг настроены один раз в `app`-слое.
- MSW интегрирован так, что включается в dev/тестах и полностью вырезается из production.
- Конвенции (границы импортов FSD, `*.component.tsx`) зафиксированы линтером/структурой, а не только на словах.

**Non-Goals:**
- Реальные Zod-схемы контракта, API-функции и MSW-хендлеры (→ `api-and-mocks`).
- Любое содержимое страниц и бизнес-логика (→ фиче-change'и).
- Выбор и глубокая кастомизация UI-кит-библиотеки — на этом этапе минимальный набор примитивов.

## Decisions

**FSD-слои и границы.** Каталоги `src/app`, `src/pages`, `src/widgets`, `src/features`, `src/entities`, `src/shared`. Импорт разрешён только «вниз» по слоям; между слайсами одного слоя — только через публичный `index.ts`. Границы форсируем ESLint (`import/no-restricted-paths` или `eslint-plugin-boundaries`) + path-алиасами в `tsconfig`/Vite (`@app`, `@shared`, …). _Альтернатива:_ плоская структура `src/components` — отклонено, ТЗ прямо требует FSD и это упрощает нарезку следующих change'ей.

**Именование компонентов.** Все файлы React-компонентов — суффикс `*.component.tsx` (жёсткое требование ТЗ). Добавим ESLint-правило/проверку именования, чтобы нарушение ловилось автоматически.

**MSW-бутстрап.** Асинхронная точка входа: в dev/тесте динамически импортируем и `await worker.start()` до рендера; в production ветка отсутствует (tree-shaking по `import.meta.env.DEV`). Воркер и seed-данные лежат в `shared/api/mock`, но наполняются в `api-and-mocks`. _Альтернатива:_ всегда стартовать воркер — отклонено, тянет мок-данные в prod-бандл.

**State-разделение.** Серверное состояние — исключительно TanStack Query (кэш, инвалидация, prefetch). Клиентский UI-state (например, драфт фильтров, состояние модалки ставки) — точечно на **MobX** (`mobx` + `mobx-react-lite`), сторы располагаются в слое конкретной фичи, а не глобально. _Альтернатива:_ Zustand — оба допускались ТЗ; выбран MobX (решение зафиксировано в explore). Правило: не дублировать в MobX то, что уже держит Query.

**Роутинг.** TanStack Router с типобезопасными маршрутами; на этом этапе `/` и `/auctions/$auctionUuid` — заглушки. Валидация search params (Zod) добавляется в `auctions-list`. Not-found и root error boundary настраиваются на уровне корневого маршрута.

**Тесты.** Vitest + jsdom как раннер для будущих unit-тестов чистой логики (парсинг search params, request builder, мапперы, схема ставки). В этом change — только конфигурация и smoke-тест, что shell монтируется.

## Risks / Trade-offs

- [MSW-код может утечь в prod-бандл] → Динамический импорт под `import.meta.env.DEV` + проверка размера/содержимого сборки smoke-скриптом.
- [FSD-границы легко нарушить вручную] → Форсируем линтером с самого начала, до появления фич, чтобы нарушения не накапливались.
- [MobX + строгий TS + React 18 StrictMode double-render] → Использовать `mobx-react-lite` `observer`, стор-фабрики без синглтон-побочек; задокументировать в `shared`.
- [Over-engineering каркаса] → Держать `shared/ui` минимальным (кнопка, карточка, skeleton, toast-хост); расширять по мере нужды фич.
