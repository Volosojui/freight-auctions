## Purpose

Страница списка аукционов: загружает и пагинирует данные, даёт фильтры с синхронизацией в URL и безопасной Zod-валидацией, отображает состояния загрузки/пустоты/ошибки, префетчит детальную и показывает адаптивные карточки с корректным основным действием.

## ADDED Requirements

### Requirement: Загрузка списка и пагинация

Страница SHALL загружать аукционы через TanStack Query по `POST /auctions/list` и SHALL поддерживать постраничную навигацию на основе `meta` (`current_page`, `last_page`, `per_page`, `total`). Переход между страницами MUST отражаться в запросе и в состоянии страницы.

#### Scenario: Первая страница

- **WHEN** пользователь открывает список
- **THEN** загружается первая страница аукционов и отображается элемент управления пагинацией на основе `meta`

#### Scenario: Переход на другую страницу

- **WHEN** пользователь выбирает другую страницу
- **THEN** запрашивается соответствующая страница, а UI отражает новый `current_page`

### Requirement: Фильтры с синхронизацией в URL и Zod-валидацией

Страница SHALL предоставлять минимум фильтров из ТЗ: `cargo_num`, `status`, `statuses`, `auc_type`, `load_city`, `unload_city` (из мок-словаря городов), дата погрузки от/до, `is_available`, `is_bidder`, цена от/до. Активные фильтры и текущая страница MUST синхронизироваться в URL search params. Search params MUST валидироваться Zod-схемой с безопасными fallback-значениями: некорректные значения в URL MUST заменяться на дефолты, а не приводить к падению страницы.

#### Scenario: Фильтр отражается в URL

- **WHEN** пользователь задаёт значение фильтра (например, `cargo_num` или статус)
- **THEN** URL search params обновляются, а список перезапрашивается с этим фильтром

#### Scenario: Некорректный URL

- **WHEN** страница открыта с некорректными или неполными search params
- **THEN** Zod-валидация подставляет безопасные fallback-значения, и страница рендерится без ошибки

#### Scenario: Восстановление состояния из URL

- **WHEN** пользователь открывает ссылку с заданными фильтрами и страницей
- **THEN** фильтры и пагинация восстанавливаются из URL, и загружается соответствующий список

### Requirement: Состояния загрузки, пустоты и ошибки

Страница SHALL показывать skeleton во время загрузки, empty-состояние при пустом результате и error-состояние с возможностью повторить запрос при ошибке.

#### Scenario: Загрузка

- **WHEN** запрос списка выполняется
- **THEN** отображается skeleton-состояние вместо контента

#### Scenario: Пустой результат

- **WHEN** список вернулся пустым (`meta.total = 0`)
- **THEN** отображается empty-состояние

#### Scenario: Ошибка запроса

- **WHEN** запрос списка завершился ошибкой
- **THEN** отображается error-состояние с действием повторить запрос

### Requirement: Prefetch детальной по intent

Страница SHALL префетчить данные детальной страницы аукциона при проявлении намерения (hover/focus по карточке), чтобы переход на детальную ощущался мгновенным.

#### Scenario: Hover по карточке

- **WHEN** пользователь наводит курсор или фокусируется на карточке аукциона
- **THEN** инициируется префетч детальной этого аукциона

### Requirement: Карточка аукциона с основным действием

Карточка SHALL отображать: номер заявки, тип аукциона (`Request`/`Up`/`Down`/`FixPrice`), статус аукциона, торговый статус пользователя, маршрут погрузка→выгрузка, даты погрузки/разгрузки, груз (название, вес, объём, тип кузова), текущую цену, цену за км, шаг ставки и флаг «моя ставка есть/нет». Карточка MUST показывать основное действие, соответствующее состоянию: «Сделать ставку», «Изменить ставку», «Смотреть ставки» либо disabled-состояние. Действие ставки MUST открываться по ссылке (навигацией на маршрут).

#### Scenario: Отображение данных карточки

- **WHEN** карточка рендерится по данным элемента списка
- **THEN** показаны номер, тип, статус, торговый статус, маршрут, даты, груз, цена, цена за км, шаг и флаг своей ставки

#### Scenario: Основное действие по состоянию

- **WHEN** аукцион недоступен для ставки
- **THEN** основное действие отображается как «Смотреть ставки» или disabled, а не как активная ставка

#### Scenario: Действие открывается по ссылке

- **WHEN** пользователь активирует основное действие ставки
- **THEN** происходит навигация на соответствующий маршрут (детальная/форма ставки), а не только локальное изменение состояния

### Requirement: Адаптивность списка

Список и карточки SHALL корректно отображаться на desktop и mobile без горизонтального скролла.

#### Scenario: Mobile-раскладка

- **WHEN** список открыт на mobile-ширине
- **THEN** карточки перестраиваются под узкий экран без горизонтального скролла
