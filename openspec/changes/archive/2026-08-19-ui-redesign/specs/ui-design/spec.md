## Purpose

Наблюдаемые UX-требования редизайна: единая адаптивная визуальная система и состояния, переключение светлой/тёмной темы с сохранением, доступность и клавиатурная навигация — при полном сохранении существующего поведения и приёмочных тестов.

## ADDED Requirements

### Requirement: Единая адаптивная визуальная система и состояния

Все экраны (app shell, список+фильтры, карточка, детальная, вкладка ставок, модалка ставки) SHALL использовать единую дизайн-систему на CSS-токенах. Каждый экран с асинхронными данными SHALL показывать состояния загрузки (skeleton), пустоты и ошибки. Раскладка MUST быть адаптивной и не давать горизонтального скролла на mobile-ширине.

#### Scenario: Единый визуальный язык

- **WHEN** пользователь переходит между экранами
- **THEN** цвета, типографика, отступы и компоненты согласованы (общие токены), без разнородных стилей

#### Scenario: Состояния данных

- **WHEN** экран с данными загружается, пуст или получает ошибку
- **THEN** отображается соответствующее состояние (skeleton / empty / error c повтором), а не пустой экран

#### Scenario: Mobile-раскладка

- **WHEN** приложение открыто на mobile-ширине
- **THEN** контент перестраивается под узкий экран без горизонтального скролла

### Requirement: Переключение светлой и тёмной темы

Приложение SHALL поддерживать светлую и тёмную темы, реализованные на токенах. В шапке MUST быть переключатель темы. По умолчанию тема SHALL следовать системной настройке пользователя; явный выбор MUST сохраняться и восстанавливаться при повторном открытии.

#### Scenario: Тема по умолчанию из системы

- **WHEN** пользователь открывает приложение впервые (без сохранённого выбора)
- **THEN** применяется тема, соответствующая системной настройке

#### Scenario: Переключение и сохранение

- **WHEN** пользователь переключает тему
- **THEN** оформление немедленно меняется, выбор сохраняется и восстанавливается после перезагрузки

### Requirement: Доступность и клавиатурная навигация

Интерактивные элементы SHALL быть доступны с клавиатуры и иметь видимое состояние фокуса. Цветовой контраст текста и ключевых элементов MUST соответствовать WCAG AA. Значимые для доступности элементы MUST иметь корректные роли/подписи (ARIA). Модальная форма ставки MUST закрываться по Esc и удерживать фокус внутри себя, пока открыта.

#### Scenario: Клавиатурная работа с формой ставки

- **WHEN** пользователь открывает форму ставки и работает только с клавиатуры
- **THEN** он может заполнить и отправить цену, а фокус остаётся внутри модалки

#### Scenario: Закрытие модалки по Esc

- **WHEN** форма ставки открыта и пользователь нажимает Esc
- **THEN** модалка закрывается и фокус возвращается к запустившему её элементу

#### Scenario: Видимый фокус

- **WHEN** пользователь перемещается по интерактивным элементам с клавиатуры
- **THEN** текущий элемент имеет чётко видимый индикатор фокуса

### Requirement: Отсутствие регрессий поведения

Редизайн SHALL менять только представление. Все существующие пользовательские потоки (список, фильтры→URL, детальная с ограничениями DTO, вкладка ставок, установка ставки с мутацией и тостами) MUST сохранять прежнее наблюдаемое поведение. Селекторы, на которые опираются приёмочные тесты (`data-testid`, роли, проверяемый текст), MUST сохраняться, и вся существующая приёмочная свита MUST оставаться зелёной.

#### Scenario: Существующие потоки не сломаны

- **WHEN** после редизайна выполняются существующие пользовательские сценарии
- **THEN** они работают как прежде (данные, навигация, фильтры, ставка), меняется только внешний вид

#### Scenario: Приёмочные тесты остаются зелёными

- **WHEN** запускается существующая свита (unit + integration + e2e)
- **THEN** все тесты проходят без изменения их проверок по существу
