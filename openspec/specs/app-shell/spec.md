# app-shell

## Purpose

Определяет каркас SPA: приложение загружается, конфигурирует data-layer и роутинг, показывает адаптивный layout и корректно обрабатывает неизвестные маршруты и ошибки рендера. На этот каркас опираются все продуктовые фичи.

## Requirements

### Requirement: Приложение загружается и рендерит app shell

Приложение SHALL монтироваться в одну корневую точку и рендерить корневой layout с областью для контента маршрута. Layout MUST быть адаптивным: корректно отображаться и на desktop, и на mobile-ширине без горизонтального скролла.

#### Scenario: Первичная загрузка

- **WHEN** пользователь открывает корневой URL приложения
- **THEN** монтируется app shell с шапкой и контентной областью
- **AND** активный маршрут рендерится внутри контентной области

#### Scenario: Адаптивная раскладка

- **WHEN** приложение открыто на mobile-ширине (< 768px)
- **THEN** layout перестраивается под узкий экран без горизонтального скролла

### Requirement: Провайдеры data-layer сконфигурированы

Приложение SHALL предоставлять единый `QueryClient` через провайдер TanStack Query всему дереву и SHALL инициализировать роутер TanStack Router. Любой компонент-потомок MUST иметь возможность использовать query- и router-хуки без дополнительной настройки.

#### Scenario: Query доступен в дереве

- **WHEN** компонент-потомок вызывает query-хук
- **THEN** он получает сконфигурированный `QueryClient` из контекста без ошибки об отсутствии провайдера

#### Scenario: Навигация между маршрутами

- **WHEN** пользователь переходит по внутренней ссылке на другой известный маршрут
- **THEN** роутер рендерит соответствующий маршрут без полной перезагрузки страницы

### Requirement: Роут-скелет списка и детальной страницы

Приложение SHALL регистрировать маршрут списка аукционов (`/`) и маршрут детальной страницы, параметризованный идентификатором аукциона (`/auctions/$auctionUuid`). На этом этапе маршруты MAY быть заглушками; параметр детальной страницы MUST быть доступен компоненту маршрута.

#### Scenario: Маршрут детальной страницы принимает параметр

- **WHEN** пользователь открывает `/auctions/<uuid>`
- **THEN** рендерится маршрут детальной страницы
- **AND** значение `<uuid>` доступно компоненту маршрута как параметр

### Requirement: Обработка неизвестного маршрута и ошибок рендера

Приложение SHALL показывать состояние «страница не найдена» для незарегистрированного маршрута и SHALL перехватывать ошибку рендера корневым error boundary, показывая fallback вместо белого экрана.

#### Scenario: Неизвестный маршрут

- **WHEN** пользователь открывает несуществующий путь
- **THEN** отображается состояние not-found с возможностью вернуться к списку

#### Scenario: Ошибка рендера перехвачена

- **WHEN** дочерний маршрут выбрасывает ошибку при рендере
- **THEN** корневой error boundary показывает fallback-состояние вместо аварийного белого экрана

### Requirement: MSW активен только в dev и тестовой среде

Приложение SHALL запускать MSW-воркер при старте в dev-режиме и в тестах, чтобы сетевые вызовы обслуживались моками. Код и данные MSW MUST быть исключены из production-бандла.

#### Scenario: Моки в dev

- **WHEN** приложение стартует в dev-режиме
- **THEN** MSW-воркер зарегистрирован и перехватывает сетевые запросы приложения

#### Scenario: Моки не в production

- **WHEN** приложение собрано для production
- **THEN** MSW-воркер не регистрируется и его код не попадает в production-бандл
